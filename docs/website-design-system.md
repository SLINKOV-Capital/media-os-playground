# Website Design System — MediaOS Public Site

Короткая спецификация **публичного сайта** (прототип).  
Общие tokens и Cockpit — `docs/design-principles.md`.  
Визуальные референсы — папка `design/` (не `docs/`).

Цель первой версии: проверить визуальный язык, типографику, отступы, навигацию, иерархию, responsive и UX. Это не финальный дизайн.

---

## Роль сайта

- Витрина опубликованных **Documents** (MediaOS — единственный источник истины).
- Персональный сайт автора (Дмитрий Слиньков), не отдельная CMS.
- Нет логина в UI; Cockpit — скрытый вход.

---

## Визуальный язык (прототип)

- Спокойная «страница», не CRM и не корпоративный лендинг.
- Контент важнее chrome; минимум карточек «ради дизайна».
- **Hero writer-site допустим** (в отличие от старого абзаца principles про «без hero» — для публичного сайта героя с портретом/брендом используем).
- Референсы по приоритету: `design/hero/` (approved Figma) → `design/inspiration/` → предложения агента.
- Не ломать Cockpit: меняется только публичная часть.

### Typography

Только две семьи. Ощущение editorial, не corporate. Много воздуха, сильная иерархия. Декор типографики — только в Hero / крупных display-заголовках.

#### Display / Hero headings

| | |
|-|-|
| **Font** | **Unbounded** |
| **Usage** | Hero wordmark (H1), крупные display-заголовки, логотип на hero, визитка |
| **Weights на hero** | Wordmark SemiBold; логотип **Bold 38.95** (41−5%); визитка **Light 28.35** |
| **Не использовать** | body, обычный UI вне hero |

#### UI / Body

| | |
|-|-|
| **Font** | **PT Root UI** |
| **Usage** | navigation вне display, body, buttons, cards, forms, article text, captions, footer |

При генерации сайта: подключить оба семейства в `app/layout.tsx` / CSS (`--font-display`, `--font-ui`). Unbounded: веса **300 / 600 / 700** минимум.

Accent for public site prototype: **`#F9461D`**.

### Tokens (публичный слой)

| Token | Значение |

### Public type scale (hybrid)

Файл: `app/globals.css` → блок `.public-site` (ищи `--type-logo`).

Fluid **390→1440**, дальше desktop-потолок.  
Формула: `clamp(MOBILE, MOBILE + (DESKTOP − MOBILE) × (100vw − 390px) / 1050, DESKTOP)`.

Крутить **три числа** в каждом токене: mobile / desktop в середине / desktop в конце.

| Токен | Desktop | Mobile | Куда применяется |
|-------|---------|--------|------------------|
| `--type-logo` | 24 | 16 | логотип header |
| `--type-ui` | 20 | 14 | гориз. меню, часы, «Связаться…» |
| `--type-menu` | 72 | 40 | полноэкранное меню (гамбургер) |
| `--type-button` | 16 | 14 | кнопки CTA |
| `--type-hero-card` | 24 | 16 | визитка в Hero |
| `--type-h1` | 40 | 28 | H1 страниц (не wordmark) |
| `--type-h2` | 24 | 16 | H2 в скобках `(Обо мне)` и т.п. |
| `--type-h3` | 20 | 16 | подзаголовки списков / consulting |
| `--type-about` | 56 | 28 | крупный текст «Обо мне» |
| `--type-body` | 20 | 16 | обычный текст, лиды |
| `--type-link` | 20 | 14 | инлайн-ссылки (резерв) |
| `--type-card-title` | 24 | 16 | заголовки карточек / разделы about |
| `--type-card-text` | 18 | 15 | текст карточек, превью start-here |
| `--type-quotes` | 16 | 13 | подписи, meta, ©, place |
| `--type-footer` | 40 | 24 | крупные пункты футера |

Hero wordmark — вне шкалы. Cockpit — не трогаем.

## Hero layout (desktop anchors)

**Эталон Figma:** **1920 × 960** (Hero ≈ 80% вертикали). В CSS: `--hero-h: 80dvh`.

- **Y / высота фото** → `px / 960 * heroH`
- **X / ширины / кегли / бургер** (≥1440) → `px / 1920 * 100vw`  
  (на 1920 = те же px; на **1440** = ×0.75)

При любом изменении отступов агент **обязан сразу обновить эту таблицу** и `--hero-*` в `app/globals.css`.

### Элементы (Figma → CSS)

| Элемент | Свойство | Figma (px @1920) | Применение в CSS |
|---------|----------|------------------|------------------|
| Логотип | X (left) | **107** | `calc(107/1920*100vw)` |
| Логотип | Font | **`--type-logo`** 16→24 (cap 1440) | header only (этап 1) |
| Гамбургер | X (left) | **1721** | `calc(1721/1920*100vw)` |
| Гамбургер | Size | **88×88**, bars **44×28** | `calc(…/1920*100vw)` |
| Визитка | X (left) | **105** | `calc(105/1920*100vw)` |
| Визитка | Y (top) | **`--hero-creds-top`** в **%** высоты hero (по брейкпоинту) | например `35%` / `42%` |
| Фото size | | **×1.21** @1024 only (+10% +10%) | figure W/H ×1.21 |

### Адаптив — статус

| Ширина | Статус |
|--------|--------|
| **1920** | Эталон, утверждён |
| **1440** | Fluid + локальные правки визитки |
| **1280** | Fluid + визитка Y 387 |
| **1024** | Fluid; фото ×1.21; визитка с локальным Y |
| **768** | Hero 60dvh; фото ×1.581; визитка ×1.53; лого+бургер по центру хедера | |
| **390 / &lt;768** | **Утверждён.** Hero 60dvh; лого 16px; визитка −100% высоты; фото ×2.025, X −20vw, top **150px** | |

### Связанные файлы

- Стили: `app/globals.css` (блок `.public-hero*`, `.public-site--hero .public-header`)
- Разметка: `app/page.tsx`, `components/PublicSiteShell.tsx`
- Ассет: `public/brand/hero.png` (источник `design/hero/hero.png`)

### Правило для агента

1. Меняешь отступ / кегль / якорь в hero → **в том же ответе** правишь таблицу выше.
2. Не хранить «секретные» отступы только в CSS.
3. Не путать **X = left** и **right** (фото: `left: 652`).
4. **Правки на брейкпоинте N применяются только к N** (через `@media`), пока пользователь явно не скажет обновить эталон 1920.
5. Сверка — Figma ↔ DevTools на **текущей** ширине.

## Процесс: Hero → адаптив → параллакс

### 1. Desktop 1920

Эталон **утверждён**.

### 2. Адаптив

Последовательно, **одна ширина за раз**:

1. **1440** — fluid + локальные правки визитки  
2. **1280** — fluid + визитка Y 387  
3. **1024** — фото ×1.21, правки визитки  
4. **768** — 60dvh + локальные правки  
5. **телефон (&lt;768, ориентир 390)** — **утверждён** 

На каждом шаге: сверять в DevTools; править точечно, если scale «ломает» композицию.

### 3. Параллакс

- Уже в прототипе: `components/HeroFigure.tsx`, factor **0.28**.
- Двигается **только фотография** (отстаёт от скролла).
- Большая надпись, Header и визитка — **неподвижны**.
- `prefers-reduced-motion: reduce` → выключено (Windows: «Параметры → Спец. возможности → Визуальные эффекты → Эффекты анимации»).

## Компоненты страниц

- **Header (hero):** fixed поверх hero (белый текст); от **1200px** — горизонтальное меню + часы + «Связаться со мной»; &lt;1200 — гамбургер. После ухода с hero — белая плашка, чёрный текст.
- **Hero:** визитка + `hero.png` + большая надпись; якоря — секция «Hero layout» выше.
- **Home after hero:** `(Обо мне)` → `(Начните отсюда)` → `(Над чем сейчас работаю)` → `(Семинары)` `#seminars` → footer `(Разделы)`.
- **Document card / row:** тип + title + preview.
- **Article body:** Markdown, спокойная типографика; колонка чтения ~**680px** по центру (Medium-measure).
- **Article (wide, backlog):** TOC auto H2/H3 слева sticky; термины справа sticky (в тексте — серый фон); mobile — sheets. Видео = linked Document (YouTube); аудио/презентация = артефакты document, не Materials; EN/ES = поля того же Document. **Recommended:** Medium 2-col grid (cover / title / preview). См. `docs/vision.md`.
- **Footer:** группы `(Разделы)+меню` и `(Соцсети)+список` плотно; контакт справа; боковые отступы = `--public-page-inset-x` (105/1920, как hero).

## Responsive

- Эталон: 1920 + Hero `80dvh` + Y-ratio (см. процесс выше).
- Узкие ширины — только после утверждения Desktop; по одной ширине за итерацию.

---

## Связь с MediaOS

- Редактирование только в Cockpit.
- Публикация = `site_status` / `site_slug` на Document.
- Сайт только читает; не создаёт контент.
