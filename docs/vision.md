# MediaOS Vision

## Что такое MediaOS

MediaOS — это личная операционная система независимого автора, редакции и издательства.

Она не создаёт контент сама.

Она помогает пройти весь путь от идеи до публикации, сохраняя знания, историю и результаты работы.

Главная цель — не автоматизировать человека, а убрать рутину, чтобы больше времени оставалось на мышление, творчество и принятие редакционных решений.

---

# Главный принцип

Любой контент проходит единый жизненный цикл:

```
Источник → Исследование → Черновик → Редактура → Медиа → Публикация → Аналитика
```

Неважно, новость это, статья, рассказ, глава книги, сценарий, видео, подкаст или презентация — **по смыслу** это один процесс.

Но в MediaOS **Новости** и **Документы** — **разные сущности**, не варианты одной таблицы.

---

# Новости vs Документы

| | Новости | Документы |
|---|---------|-----------|
| Природа | Одноразовый снаряд: опубликовал — забыл | Мини-проект: живёт, обновляется, перелинковывается |
| Редактура после публикации | Не актуализируются | Постоянно дорабатываются |
| История версий / diff | Не нужны | Нужны (поэтапно) |
| Связь с сайтом | Могут анонсировать Document или редко — целиком маленький Document | Публичный сайт (`/p/[slug]`) — основная витрина |
| Видео | Вложение к новости (ролик из сети или свой) | Отдельный Document — отдельное «большее дело» |
| Materials (Cockpit) | **Не связаны** | Глобальные materials, many-to-many с document |

**Важно:** статья про ИИ и видео про ту же тему — это **два разных Document**, а не один document в двух каналах.

**Для новостей** одна новость может уйти в Threads, LinkedIn, Telegram и т.д. — это мультипостинг **одного** news-item, а не смешение разных проектов.

Новость может **иногда** ссылаться на Document (анонс) или редко — целиком опубликовать маленький Document. Это исключение, не правило.

---

# Новости

Новости — **отдельная сущность**, не статьи блога и не `documents`.

Жизненный цикл:

```
Поиск → Отбор → Редактура → Иллюстрация → Мультипостинг → Аналитика
```

Характеристики:

- опубликовал и не возвращаешься к правкам;
- без diff и истории версий;
- видео/картинка — **вложения к новости** (Assets), не отдельный Document.

**Сбор, редакция и публикация новостей** — в **News Service** (`ai-business-news-bot`).

MediaOS **не публикует** новости в соцсети. MediaOS — **дашборд и аналитика**: факты публикаций, ссылки, позже — просмотры и лайки (общая БД или API).

### Рабочий процесс (целевой)

```
Отбор → Редактура → Иллюстрация → Настройка публикации → Publish → Аналитика
```

1. **Отбор** — кандидат из Sources (RSS, Telegram и т.д.).
2. **Редактура** — финальный текст новости.
3. **Иллюстрация** — обложка (Assets).
4. **Настройка публикации** — экран с галочками по площадкам (Threads, LinkedIn, Telegram, …); можно снять, например, «опубликовать в Telegram».
5. **Publish** — одна кнопка; постинг только на отмеченные каналы.
6. **Аналитика** — факт и URL по каждому каналу; дашборд в MediaOS.

### Paste (временно)

**Paste** — ускоренный вход «текст из буфера → Publish», чтобы быстро возобновить работу и переопубликовать backlog (например, из TG-канала).

Это **не целевой** процесс, а bootstrap на ближайшие недели. Целевой — отбор и редактура в конвейере, затем экран настройки публикации.

### Ближайший этап (News Service)

1. **Paste** — быстрый старт для backlog (временно).
2. Экран **настройки публикации** (галочки по каналам) + кнопка **Publish**.
3. Публикация с **картинкой-вложением** (обложка).
4. **Комментарий к посту** со ссылками-пруфами.
5. Мультипостинг: **Threads**, **LinkedIn** (код уже в News Service).
6. Запись **факта публикации** в общую БД — для дашборда в MediaOS.

---

# Документы

Document — единица работы в Cockpit: статья, рассказ, книга, сценарий, семинар, исследование, презентация, руководство, видео, подкаст и т.д.

Документ — **мини-проект**: actions, materials, шаблоны workflow, публикация на сайт (`content_md`, `site_slug`).

Документы **перелинковываются** и **актуализируются** после публикации на сайте.

Сделать статью — одно дело. Сделать видео по той же теме — **другое**, отдельный Document.

Публичный сайт показывает опубликованные documents. Отдельной CMS и копий контента нет — MediaOS единственный источник истины.

> MediaOS является единственным местом редактирования Documents.
>
> Website никогда не редактирует контент.

---

# Materials vs Assets

## Materials (Cockpit)

Глобальные вспомогательные объекты автора: источники, ссылки, заметки, файлы.

Связаны с **Documents** через `document_materials`.

**С новостями не смешиваются.** Текст из новости можно вручную перенести в Material.

## Assets (новости)

Сущности **подготовки новости**: обложки, иллюстрации, видео к посту.

На первом этапе — **генерация обложки** по заданному алгоритму.

С Materials физически не связаны.

---

# Основные модули

## Sources

Сбор из RSS, Telegram, YouTube, Reddit, Hacker News, GitHub, сайтов, документов пользователя.

Задача — находить потенциально интересное, **не писать**.

Для новостного конвейера сейчас реализовано в `ai-business-news-bot`.

---

## Editorial

Редакционное ядро: отбор, черновик, переписывание, стиль, фактчек, варианты.

ИИ — помощник редактора, а не редактор.

**История изменений** — для Documents (поэтапно). Для новостей — не требуется.

---

## Publishing

### Новости (News Service)

Публикация новостей выполняется **только в News Service** — не в MediaOS.

Площадки: Threads, LinkedIn, Telegram, VK, Instagram, TenChat и др.

У каждой площадки — свои правила (длина, картинка, первый комментарий, хэштеги, ссылки, время).

Перед Publish — **экран настройки**: галочки «куда постить»; одна новость может уйти в несколько каналов.

API Threads и LinkedIn: `ai-business-news-bot` (`src/threads/publisher.py`, `services/linkedin_publisher.py`).

Секреты соцсетей — env **News Service**, не MediaOS.

### Документы (MediaOS → Website)

Публикация documents — на **сайт** (`/p/[slug]`). Соцсети для document — отдельные решения позже, без модели «один document → все каналы».

---

## Analytics

История публикаций и эффективность площадок.

**v1:** только факт — где, когда, URL поста. Общий дашборд в MediaOS, в т.ч. для новостей из внешнего бота.

**Позже:** просмотры, лайки, комментарии, CTR, сравнение площадок.

---

## Knowledge

Редакционные политики, стиль, словари, шаблоны, исследования, накопленный опыт.

Используется всеми модулями. Реализация — поэтапно (файлы, materials, отдельные сущности).

# Физическая архитектура

## Связи между приложениями

### News Service → MediaOS

News Service отвечает за сбор, исследование, **редактуру и публикацию** новостей.

MediaOS **читает** результаты: статусы, URL постов, аналитика. Не дублирует posting-логику.

На первом этапе оба приложения работают с общей базой данных.

При необходимости взаимодействие может быть перенесено на API без изменения бизнес-логики.

### MediaOS → Website

Website читает опубликованные Documents из общей базы данных (или через API).

Website никогда не является источником данных и не содержит собственной CMS.

## Хостинг

Website → Timeweb

MediaOS → Vercel + Supabase

News Service → Vercel + Supabase

News Service может быть вынесен в отдельный VPS или другую инфраструктуру без изменения бизнес-логики.

# Принципы

- Публикация **новостей** — в **News Service**; MediaOS — дашборд и аналитика.
- **Paste** для новостей — временный bootstrap, не целевой UX.
- Materials и Assets новостей — **не смешивать**.
- Один Document на сайте — один источник истины (без копий для CMS).
- Разные типы контента по одной теме (статья / видео / подкаст) — **разные Documents**.
- Все изменения Documents сохраняются — **поэтапно** (сначала новости в боте, потом полная история в Cockpit).
- Любой модуль развивается независимо.
- ИИ помогает, но не скрывает ход работы.
- Пользователь видит источник и цепочку обработки.

---

# Конечная цель

MediaOS — единая рабочая среда автора.

Не набор отдельных ботов. Не коллекция скриптов. Не CMS.

Операционная система, в которой рождается, развивается, публикуется и анализируется весь контент — с допустимым поэтапным переносом функций из существующих инструментов.
