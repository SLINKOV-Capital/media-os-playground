# Terminology — MediaOS 2.0

## Операционные объекты

### Project (Проект)

Крупное дело, объединяющее задачи: книга, рассказ, видео или другое направление работы. Имеет название, описание, категорию Kanban и ручной порядок сортировки.

### Task (Задача)

Результат, которого необходимо достичь. Задача может существовать без проекта, иметь срок и отдельную отметку достижения результата. Выполнение входящих Actions само по себе не завершает Task.

### Action (Действие)

Конкретная работа для достижения результата задачи. Имеет название, заметки, собственный порядок и отметку выполнения. Action принадлежит Task, не Document.

## Публикация и материалы

### Document (Документ)

Публикационный контент MediaOS: статья, рассказ, пьеса, книга, видео и т. п. Document хранит Markdown, тип из `workflow_templates_v2`, материалы и существующие данные публикации. Его можно связать с Project/Task или создать самостоятельно. Document не является Project.

### Material (Материал)

Вспомогательный объект: источник, файл, ссылка или заметка. Obsidian хранится как внешняя ссылка `obsidian://`; содержимое vault не копируется.

### Workflow Template (Шаблон)

Управляемый тип документа и набор шаблонов для публикационных метаданных. Типы документов выбираются из `workflow_templates_v2`.

## Категории и выполнение

Kanban-колонки **Идеи**, **Намерения**, **Обязательства**, **Проекты**, **Хотелки** — категории карточек, не стадии выполнения и не типы объектов. Проекты и задачи можно перемещать между категориями. Ручной порядок внутри категории задаёт приоритет.

Срок выполнения задачи (`due_date`) — дата. Календарное событие (`event_at`) содержит дату и время. Выполнение задачи (`completed`) и действий (`done`) хранится отдельно.
